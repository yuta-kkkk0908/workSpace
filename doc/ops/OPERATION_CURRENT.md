# workSpace 自律改善システム構想

## 目的

workSpace を単なる情報収集基盤から、自律的に改善課題を発見し、実装候補を提案できるシステムへ進化させる。

---

## フェーズ1 改善候補収集

### 新規テーブル

improvement_candidate

- id
- title
- category
- source
- description
- impact_score
- effort_score
- priority
- status
- created_at
- updated_at

### 登録元

- エラーログ
- Discord通知分析
- 投資シナリオ分析
- note記事分析
- ニーズ収集結果
- AI監査レポート

---

## フェーズ2 AI監査官

週次ジョブを追加。

### 出力内容

- 今週の改善候補 TOP10
- 重複通知
- エラー発生傾向
- 利用されていない機能
- シナリオ精度低下
- 記事PV分析

結果を improvement_candidate に保存。

---

## フェーズ3 Issue自動生成

優先度が一定以上の改善候補を GitHub Issue 化。

### Issueテンプレート

- 現象
- 原因候補
- 改善案
- 期待効果
- 実装対象ファイル候補

---

## フェーズ4 Codex連携

Codex に Issue を割り当てる。

### 実施内容

- 修正案作成
- コード変更
- テスト追加
- PR作成

本番マージは禁止。
必ず人間レビューを経由する。

---

## フェーズ5 自律改善ダッシュボード

### 表示項目

- 未対応改善件数
- 改善実施件数
- 改善効果
- シナリオ精度推移
- 記事PV推移
- Discord利用状況

---

## 成功条件

- 毎週改善候補が自動生成される
- 改善候補がDBに蓄積される
- CodexがPR作成まで実施する
- 人間は承認判断に集中する

## 最終目標

「自動改修」ではなく、

改善案発見 → 実装提案 → PR作成

の自律サイクルを確立すること。
